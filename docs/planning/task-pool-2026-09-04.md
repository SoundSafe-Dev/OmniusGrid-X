### D1. Promote `main` · *carried from 2026-07-26 (#3, #39), 2026-08-08 (D1) — its FOURTH pool, now HARSH's call*

`hamad/converged-pre-main` is **659 commits ahead of `main`, 0 behind**. This has been true and

**Done when:** HARSH picks a date, or explicitly defers it with a reason.

### D2. Delegate the Claude-handled backlog, or review it first? · *new*

The 15 items above touch every lane but Hamad's, including files HARSH doesn't own
(`rag.py`, `IntakeInbox.tsx`). Before Claude works through them: does HARSH want a pass over
the list first — anything that looks mechanical but isn't, any sequencing preference, anything
htreinen or Alex should be told about before their files change under them?

**Done when:** HARSH confirms the list as-is, or flags exceptions and the rest proceed.

### D3. The contract gate's ceiling is a compatibility policy question · *carried from 2026-08-08 (D2), still unresolved*

Two shapes of "cannot pass without a deliberate behaviour change," both documented in
`docs/engineering/api-contract-gate.md`: **Pydantic strict mode** would satisfy the schema
check but break every existing client that sends `1`/`"true"` for a boolean; **typed path
converters** would fix a 422-vs-405 mismatch but touch routing across many lanes. Neither is a
defect — both are compatibility trades with a real cost, and the arithmetic naming how many
operations each is worth is now **stale** (written against a 451-operation schema; it's 552
today — see D6). This is a product call about breaking existing integrations, not an
engineering one.

**Done when:** HARSH answers whether either trade is worth taking, so the next person raising
this ratchet knows what the real target is instead of guessing from a stale number.

### D4. Kanban ships backend surface the frontend has never used · *new, product scope*

Comments, timer start/stop, time-logs, a workload view and a rules UI all exist as working
routes with zero frontend consumer — and production code still branches on `USE_MOCK` around
some of them. This has been sitting long enough that it reads less like "not built yet" and more
like "decide if it's wanted." Building out five UI surfaces is real roadmap work; cutting the
dead backend routes is a smaller, different task. Either is fine — the current state (neither)
is the one costing something, in dead code nobody trusts.

**Done when:** HARSH picks build-out, cut, or explicit "later, here's why," per surface.

### D5. The RAG document library and ComplianceAssistant · *new, cross-lane, needs sign-off before shipping*

`rag.py` already exposes document listing, ingest, delete and health — none of it reachable from
`ComplianceAssistant`, so "nothing matches" reads identically to "the corpus never loaded." An
answer with no exportable citation trail is a real gap for a compliance surface specifically.
This was explicitly marked in the source review as **"record, don't ship without
authorisation"** — it needs a PM sign-off on scope (what's exposed, what's exportable, what
scoping filter) before htreinen builds the UI, not after.

**Done when:** HARSH scopes what ships, htreinen builds it against that scope (see his section).

### D6. Recount the contract gate's stale ceiling arithmetic · *carried from 2026-08-08 (D2), mechanical once scoped*

The "realistic ceiling is not 451" section of `docs/engineering/api-contract-gate.md` was
written against a 451-operation schema and never updated through two subsequent growths (546,
now 552) — `AcceptedNegativeData` alone reads 45 today against the ~31 the old arithmetic
assumes. This is Claude-handled once D3 answers whether the two policy trades are worth taking
at all — recounting a ceiling that depends on a policy nobody has decided yet is wasted work.

**Done when:** D3 is answered, then the recount happens as part of closing it.

  falls into: does the fix already have a fully specified answer somewhere (a test's own
  register, a pattern used three times elsewhere in the tree), or does it need someone to decide
  what should happen? The first is Claude-handled; the second is a ticket.
* **HARSH holds both hats deliberately.** A PM decision blocking an engineering ticket (D4
  blocking FS-KANBAN work, D5 blocking FS-RAG-4) should get answered before the blocked item is
  picked up — starting the build ahead of the scope call is how a compliance surface ships
  something nobody signed off on.

  If a claim does not reproduce, correct the entry in place with the date, the way FS-816 and
  FS-890 were corrected mid-sprint. Three of the last four pools rotted by skipping this.

  never by raising a number to make a build pass.
